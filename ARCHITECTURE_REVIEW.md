# Architecture Review
Generated: 2026-09-03T20:55:50.562Z
Score: 64/100

## Summary
The codebase has a reasonably clean layered structure (domain/, lib/, hooks/, components/, pages/) with good separation of pure calc logic from storage and UI. However, there is heavy copy-paste duplication of small utilities (haptic-feedback wrappers, tab configs, category/age-band labels), two competing storage abstraction layers, several dead/orphaned files (a stale contract.ts and an unwired CancelChecklist.tsx page), and inconsistent conventions (import aliasing, async vs sync state patterns) that should be consolidated.

## Issues
### Critical
- [duplication] The exact same 'fire haptic feedback with try/catch to survive non-WebView environments' function is redefined independently in ~10 files instead of being a single shared utility. — Files: src/components/BottomCTA.tsx, src/components/DdayCard.tsx, src/components/FloatingTabBar.tsx, src/components/SubscriptionList.tsx, src/pages/Checklist.tsx, src/pages/Compare.tsx, src/pages/More.tsx, src/pages/Premium.tsx, src/pages/SubscriptionDetail.tsx, src/pages/SubscriptionEdit.tsx, src/pages/SubscriptionNew.tsx / Fix: Extract a single `fireHaptic(type)` helper into e.g. `src/lib/haptics.ts` and import it everywhere; delete the local copies.

### Warnings

Callers inconsistently pick one or the other (e.g. More.tsx uses lib/storage's removeItem while every domain module uses domain/storage's readJson/writeJson). — Files: src/lib/storage.ts, src/domain/storage.ts, src/pages/More.tsx / Fix: Delete src/lib/storage.ts and route all storage access through src/domain/storage.ts (the more robust implementation), updating More.tsx's reset logic accordingly.
- [dead_code] src/lib/contract.ts declares a full parallel set of domain types (Subscription, Settings, ChecklistItem, RouteState, and Fn signatures) that conflict in shape with the real, actually-used types in src/lib/types.ts (e.g. ChecklistItem.task/completed/order vs the real label/done/doneAt). Comments in domain/checklists.ts and domain/settings.ts explicitly acknowledge this file is a stale draft, yet it remains in the tree as a landmine for future edits/imports. — Files: src/lib/contract.ts, src/lib/types.ts, src/domain/checklists.ts, src/domain/settings.ts / Fix: Remove contract.ts (or clearly mark/relocate it as historical/non-authoritative documentation outside src/) now that lib/types.ts is the fixed, test-locked contract.

- [duplication] The bottom tab config array (홈/비교/더보기 with identical paths) is redeclared verbatim in three page files instead of a shared constant. — Files: src/pages/Home.tsx, src/pages/Compare.tsx, src/pages/More.tsx / Fix: Move `TABS: TabItem[]` into a shared module (e.g. src/lib/nav.ts) and import it in all three pages.

### Suggestions
- [duplication] CATEGORY_LABELS (CategoryKey → Korean label map) is duplicated identically in two pages, and AGE_BANDS is duplicated identically in two other pages. — Files: src/pages/Home.tsx, src/pages/SubscriptionDetail.tsx, src/pages/Compare.tsx, src/pages/More.tsx / Fix: Move CATEGORY_LABELS and AGE_BANDS into src/lib/constants.ts alongside SERVICE_TEMPLATES/DEFAULT_CHECKLIST and import from there.
- [consistency] Import style is inconsistent between the `@/` path alias and relative paths for the same modules across the codebase — domain/calc.ts, domain/checklists.ts, and DdayCard/SubscriptionList use `@/lib/types`/`@/domain/calc`, while nearly every page (Home, Compare, More, Premium, Checklist, SubscriptionDetail, SubscriptionEdit, SubscriptionNew) uses `../lib/types`/`../domain/calc` for the identical import. — Files: src/domain/calc.ts, src/components/DdayCard.tsx, src/pages/Home.tsx, src/pages/Checklist.tsx / Fix: Standardize on the `@/` alias everywhere (already configured and used by newer files) and run a repo-wide codemod/lint rule (e.g. `import/no-relative-parent-imports`) to enforce it.
- [duplication] NAME_MAX/MEMO_MAX (and NOTE_MAX) field-length constants are redefined locally in SubscriptionNew.tsx and SubscriptionEdit.tsx with the same values already enforced inside domain/subscriptions.ts (NAME_MAX, MEMO_MAX). — Files: src/pages/SubscriptionNew.tsx, src/pages/SubscriptionEdit.tsx, src/domain/subscriptions.ts / Fix: Export NAME_MAX/MEMO_MAX from domain/subscriptions.ts (or lib/constants.ts) and import them in both form pages so validation limits can't drift out of sync with UI hints.
- [naming] Two near-duplicate domain models exist for the same entity with different field names/shapes: SubscriptionRecord/SubscriptionPriceChange (domain/subscriptions.ts) vs Subscription/PriceChange (lib/types.ts), bridged only by a manual toSubscription() converter, increasing cognitive overhead when reading either file in isolation. — Files: src/domain/subscriptions.ts, src/lib/types.ts / Fix: Document the divergence prominently at both type definitions (partially done already) or, better, unify on one shape and adapt the persisted-record layer to match, removing the converter.
- [dead_code] src/lib/utils.ts exports `cn` and `formatCurrency`, but the codebase's actual currency formatting goes through `formatCurrencyKrw` in domain/calc.ts everywhere shown; cn() has no visible call sites among the 42 files, and formatCurrency is only used once (SubscriptionNew.tsx) despite formatCurrencyKrw being the established domain formatter used elsewhere for the same purpose. — Files: src/lib/utils.ts, src/pages/SubscriptionNew.tsx, src/domain/calc.ts / Fix: Verify usage with a repo-wide grep; remove `cn` if truly unused, and standardize on a single currency formatter (formatCurrencyKrw) instead of maintaining two.
